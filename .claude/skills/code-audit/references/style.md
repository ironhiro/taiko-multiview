# 코드 스타일 점검표

이 저장소의 결을 기준으로 본다. 일반론(“함수는 짧게”)보다 **주변 코드와 다른 곳**을 찾는다. 린터가 없으므로 사람이 지켜 온 관례가 기준이다.

## 이 저장소의 관례 (근거가 되는 기존 코드를 읽고 확인할 것)
- 주석: 영어, 완결된 문장, **왜**를 설명한다. 무엇을 하는지 되풀이하는 주석은 없다. 예: `Program.cs`의 CSP 주석, `PlayerTile.tsx`의 감시 타이머 설명.
- 이름: 길고 구체적(`ClosedPollIntervalSecondsClamped`, `resyncWhenShownAgain`). 약어·한 글자 변수는 루프 외에 드물다.
- 테스트 이름: 동작을 문장으로(`Newest_broadcast_wins_over_...`, `'keeps a hidden player while there is room'`).
- 커밋 메시지: 영어 서술형 제목, 본문에 이유.
- 사용자에게 보이는 문구는 한국어. 코드·주석은 영어. 섞이면 지적.
- CSS: 색은 `tokens.css` 변수만(하드코딩 색 금지), 역할 색 규칙(돈=송출, 카=선택, 매장 accent는 정체성) — `design.md`와 `tokens.css` 머리말. 간격·글자 크기도 토큰.
- C#: 파일 범위 네임스페이스, 주 생성자, `sealed`, nullable 활성. 옵션 클래스는 `SectionName` 상수.
- TypeScript: 함수 컴포넌트, 명명된 내보내기, `lib/`의 순수 함수에는 테스트 파일이 같은 폴더에.

## 볼 것
- 관례에서 벗어난 새 코드(주석 언어·문체, 이름 방식, 하드코딩 색·px).
- 죽은 코드, 쓰이지 않는 내보내기·CSS 클래스(선택자 grep으로 확인), 주석 처리된 코드.
- 같은 로직의 복붙(특히 CSS 미디어쿼리 블록 간, 백엔드 투영 함수).
- 오해를 부르는 이름이나 오래된 주석(코드가 바뀌었는데 주석이 옛 동작을 설명).
- 타입: `any`, 과한 `as` 캐스팅, `!` 남용.
- 매직 넘버: 이름 없는 상수(단, 이유 주석이 붙은 상수는 관례상 허용).

## 심각도
스타일은 대부분 low/info다. 오래된 주석이 **잘못된 동작을 설명**해 다음 수정자를 오도할 정도면 medium까지.
